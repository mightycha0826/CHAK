# 착(CHAK)

NFC 카드를 이식한 **상품 「착」** 을 들고 한 장소 *안*을 돌며, 지점마다 도장을
받아 모으는 phygital 답사 상품.

**실제 NFC로 동작한다.** proxmark3를 지점에 두고 착을 대면 카드에 방문 기록이
새겨지고, 나중에 그 착을 폰에 대면 수첩으로 옮겨진다.

- 무대 **현충사**(충남 아산) — 5개 지점
- 무대 **신라스테이 천안** — 실내 무대 예시 (콘텐츠만 유지)

스택: Vite · React 19 · TypeScript · Tailwind v4 · Motion.

화면은 하단 탭 3개 — **답사**(진행 요약 · 관내도 · 지점 목록) / **수첩**(모은 도장) / **무대**(장소 선택).

---

## 무엇이 어디에 저장되는가

이 프로젝트에서 가장 오해하기 쉬운 부분이다.

| | 담당 | 역할 |
|---|---|---|
| **착 카드** | 관람객이 구매·소지 | **진실의 원천.** 방문 기록이 여기 쌓인다 |
| **지점 리더** (PM3) | 각 지점에 상주 | 착에 「여기 왔다 + 시각」을 **쓴다** |
| **폰 앱** | 관람객 | 착을 **읽어** 수첩에 등록한다 |
| `localStorage` | 폰 | 캐시일 뿐. 착이 없어도 진행을 보여주기 위한 것 |

즉 **도장은 앱에서 찍을 수 없다.** 현장 리더에 착을 대야 카드에 새겨지고,
앱은 그걸 옮겨 담기만 한다. 착 한 장이 여러 지점을 돌고 오므로 **폰에 한 번
대면 도장이 여러 개 한꺼번에 들어오는 게 정상이다.**

방문 시각도 등록 시각이 아니라 카드에 찍힌 **현장 시각**을 쓴다. 집에 가서
등록해도 수첩에는 현충사에서 찍은 시각이 남는다.

## 카드 데이터 포맷

`src/chak/card.ts` 하나가 폰과 PM3의 공통 규칙이다. 스펙 문서가 따로 없고
**그 파일이 스펙이다.**

NDEF 텍스트 레코드 하나에 방문 기록을 담는다. Web NFC는 NDEF만 볼 수 있고
원시 블록 접근이 아예 없으므로, 카드 내용이 NDEF가 아니면 브라우저는 아무것도
못 읽는다.

```
blk  4  |.^..ZT.enCHAK1::|   헤더 (TLV + NDEF + 매직)
blk  5  |................|   슬롯 0  충무공이순신기념관
blk  6  |NANJ260723101230|   슬롯 1  난중일기 — 방문함
blk  8  |................|   슬롯 2  이순신 장검
blk  9  |GOTA260723114005|   슬롯 3  고택 — 방문함
blk 10  |................|   슬롯 4  본전
blk 12  |................|   TLV 종단
```

슬롯 하나는 16바이트 ASCII — `<지점코드 4><YYMMDDhhmmss 12>`. 미방문은 `.` 16개.

**설계의 핵심은 슬롯을 MIFARE 블록 경계에 정확히 맞춘 것이다.** 헤더에 7바이트
매직(`CHAK1::`)을 채워 넣어 슬롯이 블록과 1:1로 겹치게 했고, 덕분에 지점
리더는 **카드를 읽지 않고 자기 블록 하나만 덮어쓰면 된다** — 명령 한 줄이다.
읽고·해석하고·덧붙여 다시 쓰는 방식이었다면 현장 리더가 실패할 수 있는 지점이
세 배로 늘어난다.

전부 ASCII로 둔 이유는 `hf mf dump` 출력에서 눈으로 바로 읽히기 때문이다.
현장에서 디버깅할 때 이게 결정적이다.

> ⚠️ **카드에 도메인이 들어가지 않는다.** 등록은 앱을 켠 채 대는 인앱 스캔이
> 담당하므로 URL이 필요 없고, 덕분에 **배포 도메인이 정해지지 않아도 지금
> 카드를 발급할 수 있다.** 도메인이 바뀌어도 이미 판 착은 그대로 유효하다.

## proxmark3로 착 다루기

### 0. 스크립트 생성

```bash
npm run cards -- --stage hcs
```

`pm3/chak_init.lua`(발급) · `pm3/chak_stamp.lua`(현장 리더) · `pm3/README.md`가 나온다.

두 `.lua`를 PM3 클라이언트의 `luascripts/`에 복사한다.

### 1. 착 발급

빈 매직카드를 착으로 만든다.

```
script run chak_init
hf mf ndefread
```

공장 출하 상태의 새 카드면 `-n`으로 `cwipe`를 건너뛴다. 이미 발급한 카드를
다시 발급하려면 `ndefformat`이 공장 기본키를 요구하므로 `cwipe`가 필요한데,
Gen1a 매직카드는 백도어가 있어 **키를 잃어버려도 벽돌이 되지 않는다.**

### 2. 현장 리더

지점마다 이 명령을 띄워둔다. 착이 올라오면 자동으로 찍히고, 카드를 뗄 때까지
기다렸다가 다음 손님을 받는다.

```
script run chak_stamp -s nanjung
```

지점 목록은 `-l`, 한 장만 찍고 끝내려면 `-1`.

> ⚠️ 시각은 리더 PC의 로컬 시각을 그대로 쓴다. 설치 전에 시계를 맞출 것.

### 3. 카드 내용 확인

```
hf mf dump
```

슬롯이 ASCII라 덤프에서 `|NANJ260723101230|`처럼 바로 읽힌다.

## ⚠️ MIFARE Classic의 한계

착 카드를 MIFARE Classic으로 가는 한 **앱 코드로 우회할 수 없는 제약**이 있다.

MIFARE Classic은 NFC Forum 표준 태그가 아니라 NXP 독자 규격이다. 따라서

- **안드로이드** — NXP 계열 NFC 컨트롤러를 단 기기에서만 읽는다
- **아이폰** — 아예 못 읽는다. iOS Core NFC는 NFC Forum Type 1~5만 지원한다

폰이 착을 읽지 못하면 등록 경로가 통째로 막힌다. NTAG213/215로 바꾸면 모든
안드로이드·아이폰에서 읽고 쓸 수 있으며, **`card.ts`의 슬롯 배치만 NTAG 페이지
단위(4바이트)로 다시 계산하면 되고 앱 코드는 그대로다.**

---

## 폴백 — 태그 없이도 시연이 멈추지 않는다

Web NFC를 못 쓰는 환경(데스크톱·iOS·평문 HTTP)에서는 스캔 화면의 원을 눌러
진행한다. 폴백도 **실물 카드와 똑같은 등록 경로**를 타므로 시연에서 보이는
동작이 실제 동작과 어긋나지 않는다.

## 발표 시연 도구

답사 탭 우상단 리셋 아이콘:

- **짧게 누르면** 현재 무대 초기화 → 온보딩
- **길게(0.6초) 누르면** 숨은 시연 패널 — 심사위원 눈에는 보이지 않는다
  - **여러 곳 돌고 온 착 읽기** `2곳` · `3곳` · `5곳` — 착의 핵심 장면
  - 진행 상태 프리셋
  - **착 발급 (폰으로)** — PM3 없이 빈 착 만들기
  - **지점 도장 (폰을 현장 리더로)** — PM3를 지점마다 둘 수 없을 때

「3곳 방문」을 누르면 도장 세 개가 순차로 공개된다. **여러 곳을 돌고 한 번에
등록하는 것**이 착의 핵심이므로, 발표에서 이 장면을 보여주는 게 가장 강하다.

## 무대·콘텐츠 추가

1. `src/content/stages/<새무대>.ts`에 `Stage` 하나를 만든다
2. `src/content/index.ts`의 `STAGES` 배열에 한 줄 추가
3. `npm run cards -- --stage <새무대>`

> ⚠️ 지점을 추가·삭제하면 슬롯 배치가 통째로 바뀐다. **이미 발급한 카드는 옛
> 배치를 갖고 있으므로 다시 발급해야 한다.** 지점 코드(id 앞 4글자)가 겹치면
> 생성 단계에서 에러가 난다.

실내 무대는 `map.geo`를 비워두면 도식 관내도로 떨어진다.

> ⚠️ 현충사의 `map.geo` 좌표는 **근사값**이다. 현장에서 미세조정할 것.

## 검증

```bash
npm run dev      # 다른 터미널
npm run e2e      # 설치된 크롬으로 전체 플로우 자동 검증
```

온보딩 → 착 읽기 → 도장 → 다중 등록 → 중복 방지 → 수첩 → 완주 인증 → 무대
전환까지 훑고, 단계별 스크린샷을 `.e2e-shots/`에 남긴다.

> 구버전 `chak` / `chak-web`이 5173을 물고 있으면 Vite가 조용히 5174로 밀린다.
> e2e는 제목으로 우리 앱인지 확인하고 포트를 고르므로 신경 쓰지 않아도 된다.

```bash
npm run build    # 타입 체크 + 프로덕션 빌드
```
